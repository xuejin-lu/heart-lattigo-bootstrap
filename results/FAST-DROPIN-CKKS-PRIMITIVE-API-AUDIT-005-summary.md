# FAST-DROPIN-CKKS-PRIMITIVE-API-AUDIT-005

Classification: `FAST_DROPIN_PRIMITIVE_PARTIAL`
Handoff: `READY_FOR_WEB_REVIEW`

## Finding

The same ordinary frontend works numerically for `Add`, `MulRelin`, `Rescale`, and `Rotate` in this bounded profile, but the Fast build does **not** select the Q-prefix Fast evaluator. In both dependency trees, `ckks.NewEvaluator(params, evk)` constructs an embedded `*rlwe.Evaluator`; the Fast `schemes/ckks/fast.NewEvaluator` is a separate explicit API and intentionally does not implement the ordinary CKKS evaluator interface. The run therefore validates the unchanged public path against a Q-prefix-complete ciphertext, not the optimized Fast evaluator implementation.

Fast-layout keys are not interchangeable with the generic Standard key-switch path. Source inspection found explicit rejection in Fast `MemEvaluationKeySet.GetRelinearizationKey` / `GetGaloisKey`, `rlwe.Evaluator.ApplyEvaluationKey`, and `GadgetProduct` / `GadgetProductLazy`. The shared frontend used only ordinary `ckks.NewKeyGenerator` keys in both builds and did not pass Fast-layout keys to Standard execution. No negative key-switch operation was attempted.

## Source map

- Pinned Standard and Fast `schemes/ckks/evaluator.go` are byte-identical (SHA-256 `6b29ea57747b5d5d97c23182c0ba0c4b18ce9c7b874fbe54ee0936a34dca1a14`). `ckks.NewEvaluator` embeds `rlwe.NewEvaluator`: `schemes/ckks/evaluator.go:16-31`; generic constructor: `core/rlwe/evaluator.go:24-61`.
- Generic `MulRelin` performs RLWE relinearization/key switching: Standard `schemes/ckks/evaluator.go:742-795`; the call obtains a relinearization key and applies `GadgetProduct` in the continuation of `mulRelin`.
- Generic `Rotate` calls `Automorphism`: `schemes/ckks/evaluator.go:1188-1201`; `core/rlwe/evaluator_automorphism.go:13-45` retrieves a Galois key and applies `GadgetProduct`.
- Fast is an explicit boundary, not constructor dispatch: `schemes/ckks/fast/evaluator.go:13-32`; the Fast evaluator explicitly does not implement `schemes.Evaluator` at `schemes/ckks/fast/evaluator_ntt.go:14-20`. Its `MulRelin`, `Rescale`, and `Rotate` implementations are in `schemes/ckks/fast/evaluator_ntt.go:209-245`, `schemes/ckks/fast/rescale.go:140-159`, and `schemes/ckks/fast/evaluator.go:341-358`.
- Fast evaluation-key material is generated by `schemes/ckks/fast/keys.go:14-20,51-102`. The bounded bootstrapping `GenEvaluationKeys` route selects `GenFastEvaluationKeys` for its supported profile at `circuits/ckks/bootstrapping/keys.go:73-78`; that helper imports and invokes the Fast key generator at `circuits/ckks/bootstrapping/fast_keys.go:3-12,67-80`.
- Native Standard execution rejects Fast layout at `core/rlwe/keys.go:541-550,568-579`, `core/rlwe/evaluator_evaluationkey.go:36-42`, and `core/rlwe/evaluator_gadget_product.go:16-19,111-114`.

The first API-level incompatibility is at evaluator construction/selection: the unchanged `ckks.NewEvaluator` has no Fast dispatch. The smallest justified next library task is to define an internal, backend-transparent Fast execution path behind the unchanged CKKS public evaluator surface for these primitives, without sending Fast-layout keys through native KeySwitch. The precise compatibility contract should be frozen by Web before implementation.
