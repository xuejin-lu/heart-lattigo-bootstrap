# Batch024 independent-clone helper bug fix — Web review

**Date:** 2026-10-11, Asia/Taipei. **Scientific state:** still S4 unstarted, Batch024 0/2 reserved calls, 0 Bootstrap, per latest Codex report. This patch is purely a zero-call environment gate fix.

The first direct-Web clone patch created the correct detached task-owned local Git clone, but its last check rejected the clone when two different *path strings* named the same directory. On macOS temporary paths can be reported by Git in canonical form, whereas Go's caller retains a noncanonical alias (for example /var and /private/var). `filepath.Clean` is lexical: it never establishes filesystem identity. A valid cloned .git could therefore fail `filepath.Clean(cloneGit) == filepath.Join(filepath.Clean(targetRoot), ".git")`.

**Fix:** `createPublicE32IsolatedClone` now `Lstat`-checks that `targetRoot/.git` is a real directory, `Stat`-checks the Git-reported diagnostic/source Git dirs, and compares their actual filesystem identity with `os.SameFile`. It must match the task-owned clone and must **not** be the source repo's metadata directory. Errors now include the compared paths. No Secondary source, ciphertext, numerical checks, attempt quota, output paths, or oracle are changed.

**Regression:** new `TestPublicE32IsolatedCloneAcceptsCanonicalizedTempAliases` constructs a tiny local source Git repository, accesses the checkout through an aliased parent directory, asserts that the lexical Git path differs from the aliased path, then checks successful exact detached commit, clean working tree and safe clone cleanup. The prior stale-metadata test remains. Web ran a standalone isolated Go/Git test of this directory-identity approach under a symlink alias on Linux and it passed, but **did not run the full current repository on macOS**.
