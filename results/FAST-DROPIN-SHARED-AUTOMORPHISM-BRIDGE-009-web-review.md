## Deliberate remaining boundary

P0 public Fast uses all logical active Q rows and is a numerical **full-Q**, not compact-Q, execution path. C0 explicit Fast retains its compact prefix. Full allocated backing and `c1=0` alone **cannot establish that an arbitrary ciphertext's rows are mathematically current**: mixed P0→C0→P0 lifecycles must not be presumed valid. Any subsequent public integration must either remain strictly source-proven P0 or introduce a separately reviewed representation provenance/materialization contract; do not silently read stale higher rows. The existing public Full-Q MulRelin from 006A is preserved; no claim that it now dispatches to the separate optimized Fast prefix MulRelin or Rescale.

**Next research priority:** verify the already existing public E32 Bootstrap and P0 public Rotate can compose in **one identical Standard/Fast frontend** under the canonical LogN13 Bootstrap profile, with no production modifications, rather than immediately refactoring another primitive. Prior Bootstrap 004 and primitive 009 were each verified separately. This first system-integration check can use Level-0 public Add and Rotate (both depth-free) before Bootstrap and independent complex plaintext oracle, avoiding unproven depth/scale compatibility. It does not solve P0/C0 coexistence or CNN workloads. Proposed task 010, bounded to one Standard and one Fast Bootstrap if both preflights pass.
