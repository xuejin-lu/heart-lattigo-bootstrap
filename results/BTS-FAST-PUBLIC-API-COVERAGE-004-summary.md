## D. Bounded No-Trace run and remaining limitations

Attempt 01 is complete and failed in ScaleDown; this Batch has **1/2 actual invocations**. `NewBTS()` succeeded in 45.687 s, the encrypted input was `L3` / Scale `2^32`, and the one `bts.Bootstrap()` call returned `cannot Fast CKKS zero-secret Mul: input ciphertext has invalid dimensions or logical Level` before any output was produced. The first failing API is the ordinary integer scalar `Mul` in `MyScaleDown`: S2C consumes the three levels from `S2CStartLevel=L3`, so the scalar operation receives `L0`; current Fast adapter wrongly requires both q0 and q1 although the integer operation consumes no level and the shared Q-prefix width at L0 is q0 only. This was fixed and regression-tested in Secondary commit `d1b6dc9963b0df95a7c149306fb62660e1020f7b`. In accordance with the bounded charter, distinct attempt 02 has a new binary SHA and is durably reserved but not launched; launch requires that reservation commit to be pushed and verified. The evidence and full attempt-01 raw log are in the [journal](BTS-FAST-PUBLIC-API-COVERAGE-004-journal.md). Neither binary may be relaunched.

The existing Standard result is historical and will not be rerun: Bootstrap 139.653 s, max absolute error `1.708e-3`, mean absolute error `1.172e-4`. Do not compute a speedup unless this Batch produces a complete Fast output with comparable metrics.
